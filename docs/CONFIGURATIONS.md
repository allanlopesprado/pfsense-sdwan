# How native pfSense settings affect SD-WAN

This matrix covers the package's dependencies on pfSense CE 2.9.1. On stock CE, the observer reads dpinger and recommends a path. The experimental core can apply that recommendation to explicitly bound rules. A recommendation reflects the probe's conditions. Verify delivery to the application destination separately. [Integration and forwarding](INTEGRATION.md)

| pfSense settings | Effect on SD-WAN | Evidence |
| --- | --- | --- |
| **System → Routing → Gateways**. Delete, rename, or disable a gateway, or change its interface, next hop, IP family, or Monitor IP. | A member can lose its reading and become ineligible. Saving a change between observation cycles invalidates the previous sample until a new reading arrives. Editing an unmonitored gateway preserves the sample. | Daemon with Unix sockets, configuration changes between samples, Status, Diagnostics, widget, and core rule generation. |
| **Gateway Monitoring**. Disable probing, force a gateway down, disable the alarm action, or change RTT and loss thresholds, intervals, and window. | A member needs a valid probe result to be recommended. Disabling the action still permits measurement. A member with 100% loss is ineligible. Native alarm thresholds and policy SLA limits have different roles. | Policy engine, daemon, invalidation on save, and transitions with real dpinger in a VM. [Gateway Settings](https://docs.netgate.com/pfsense/en/latest/routing/gateway-configure.html) |
| **System → Advanced**. Change whether dpinger installs static monitor routes. | The change invalidates the previous reading. Ensure each target remains reachable over its intended path. | Invalidation test. Verifying the probe's actual route and NAT requires a capture on a clone. [Troubleshooting Multi-WAN](https://docs.netgate.com/pfsense/en/latest/troubleshooting/multi-wan.html) |
| **Interfaces**. Unassign or disable an interface, or change its port, VLAN, QinQ, bridge, or LAGG. | The old association can become unavailable. Distinct logical interfaces can depend on the same physical link. | Inventory, reassignment, and dependency preflight. Switching real ports, tags, and states requires clones. |
| **Interfaces**. Renew DHCP or PPPoE, change DHCPv6-PD and RA, or change the source address or next hop. | The daemon compares the source, destination, and IPv6 scope with the running monitor. It detects dynamic changes that do not change the saved configuration during the next observation cycle. | DHCP and PPPoE with real software on Ubuntu, IPv6 renumbering, and socket tests. Native CE service integration requires clones. |
| **Routing**. Edit tiers, triggers, the default route, static routes, FRR, or rules for local destinations. | The firewall's default route and local services follow the native routing table. In the experimental core, group, tracker, or rule changes may invalidate a binding. Verify routes and groups with new traffic. | Preflight, native rule generator, and FreeBSD. Active FRR and default route changes require separate tests. [Policy Routing](https://docs.netgate.com/pfsense/en/latest/multiwan/policy-route.html) |
| **Firewall**. Reorder rules, edit aliases or reply-to, change state killing or state policy, or change outbound NAT or port forwards. | An eligible gateway can carry traffic on the wrong path or lose return traffic when PF and NAT disagree. A rule reload can affect new and existing sessions differently. | PF in a VM, per-interface NAT, new and established connections, and return traffic through another WAN. Hybrid, manual, 1:1, and reflection NAT, NPt, and NAT64 require separate topologies. [Multi-WAN and NAT](https://docs.netgate.com/pfsense/en/latest/multiwan/nat.html) |
| **VPN**. Change Phase 1, VTIs, selectors, peer routes, MTU, or access rules. | A Monitor IP measures its own destination. Two tunnels over one WAN can fail together. Policy-based IPsec can fail while the WAN remains eligible. | IKEv2 with strongSwan, OpenVPN and WireGuard on Ubuntu, and PF/VTI/ESP on FreeBSD. End-to-end CE testing with a FortiOS peer remains pending. [VTI](https://docs.netgate.com/pfsense/en/latest/vpn/ipsec/routed-vti.html) |
| **System → High Availability Sync and Virtual IPs**. Change CARP, pfsync, VIPs, or XMLRPC. | Each node requires the package and local telemetry. Verify session continuity and package configuration synchronization independently. | CARP and pfsync in VNET with a TCP session. Two CE 2.9.1 nodes running IKEv2 during failover require a separate lab. [XMLRPC Sync](https://docs.netgate.com/pfsense/en/latest/highavailability/xmlrpc-sync.html) |
| **System → General / Services → DNS Resolver**. Change DNS, proxy, time, TLS, the egress route, or firewall-originated traffic rules. | Version checks require authenticated HTTPS to GitHub. External failures prevent the update and preserve the installed package. ICMP probing uses its own settings. | Updater transport tests cover HTTP failure, digest, ABI, truncated files, and isolated installation. [DNS and Multi-WAN](https://docs.netgate.com/pfsense/en/latest/multiwan/interfaces-and-dns.html) |
| **System → User Manager / Status → Services**. Delegate privileges or stop the observer. | Page access, logs, service controls, and package installation follow native privileges. Dependent pages wait for current data after the service resumes. | Pinned native components in Actions, forms, CSRF, privileges, and service states. A real RADIUS or LDAP backend requires a clone. [Privileges](https://docs.netgate.com/pfsense/en/latest/usermanager/privileges.html) |
| **Diagnostics → Backup & Restore / System → Update**. Restore without packages, restore with remapped interfaces, upgrade pfSense, or remove the package. | A backup that skips packages omits package configuration. Old gateway references may become unavailable after remapping. Updates checks the pfSense version and ABI before installing. | XML configuration, unavailable references, installation, upgrade, and rollback. A complete system upgrade or migration restore requires a clone. [Backups](https://docs.netgate.com/pfsense/en/latest/backup/configuration.html) |
| **Services and additional packages**. Traffic Shaper, Captive Portal, IDS/IPS, proxies, Dynamic DNS, local DHCP, and RRD. | Changes to forwarding, the return path, or probe responses can affect the delivered service. The package measures the gateway target. | The rule generator checks preservation of independent rules. End-to-end compatibility requires tests with each installed combination. |

On a clone, compare **Status → Gateways**, **SD-WAN → Diagnostics**, the loaded PF rule, and a real transaction before the change, during failure, and after recovery. Record whether the original session survived and which path a new session used. [Recorded evidence](RESULTS.md) · [Lab procedure](LAB.md) · [Package compatibility](PACKAGE-COMPATIBILITY.md)
